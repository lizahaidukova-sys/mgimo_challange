# Решения (ADR)

Короткие записи о неочевидных выборах. Формат: контекст → решение → цена → пересмотр.

## ADR-001: SQLite вместо Postgres

**Контекст.** Прототип, один инстанс, демонстрационные данные, дедлайн 2 суток.
**Решение.** `node:sqlite` (встроенный модуль), файл вне git, схема создаётся кодом и сидом.
**Цена.** Нет горизонтального масштабирования и конкурентных записей на нагрузке.
**Пересмотр.** При переходе на реальные данные — Postgres, репозитории уже изолируют SQL.
**Почему не better-sqlite3.** Требует node-gyp и компилятор: чистый `npm ci` на Node 24 без Visual Studio падал. Встроенный модуль убирает сборку из требований; цена — экспериментальный статус API и предупреждение в stderr (подавлено флагом `--disable-warning=ExperimentalWarning`).

## ADR-002: Серверные сессии вместо JWT

**Контекст.** Нужен отзыв доступа и роли без доверия клиенту.
**Решение.** Случайный токен в `httpOnly` cookie, в БД — SHA-256 от токена.
**Цена.** Запрос к БД на каждый запрос (в прототипе — дёшево).
**Пересмотр.** Кэш сессий в памяти при росте нагрузки.

## ADR-003: Светофор считается правилами, не моделью

**Контекст.** ИИ может ошибиться, решение влияет на учебный план.
**Решение.** Статус и приоритет — детерминированный код; LLM только переформулирует готовый текст.
**Цена.** Меньше «гибкости», правила надо поддерживать.
**Пересмотр.** Если появится утверждённая методика с весами — заменить правила её формулой.

## ADR-004: Нет ORM

**Контекст.** 12 таблиц, простые запросы, важна читаемость для проверки безопасности.
**Решение.** Явный SQL в репозиториях, параметризованные запросы.
**Цена.** Ручная работа при изменении схемы.
**Пересмотр.** При росте числа сущностей — Drizzle или Kysely.

## ADR-005: Один сотрудник деканата

**Контекст.** Нужно показать обработку заявок, а не строить админку вуза.
**Решение.** Роль `staff` без внутренней иерархии и распределения заявок.
**Цена.** Нет сценария «передать заявку коллеге».
**Пересмотр.** При пилоте — роли и назначение исполнителя.

## ADR-006: Демо без LLM по умолчанию

**Контекст.** Жюри должно открыть ссылку и увидеть всё работающим; ключи не должны лежать в репозитории.
**Решение.** Все сценарии работают без ключа; LLM включается переменной окружения.
**Цена.** Без ключа объяснения шаблонные.
**Пересмотр.** Не требуется: это осознанный режим.

## ADR-007: Движение данных только через server actions

**Контекст.** Публичный REST расширяет поверхность атаки и требует отдельной авторизации.
**Решение.** Мутации — server actions с проверкой сессии, роли и zod-валидацией.
**Цена.** Сложнее подключить внешнего клиента.
**Пересмотр.** При появлении мобильного приложения — отдельный API-слой с теми же проверками.
