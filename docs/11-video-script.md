# Сценарий видео (≤ 5 минут)

Записывается автоматически в двух видах:

```bash
node scripts/record-demo.mjs --view mobile    # docs/demo/demo-mobile.mp4
node scripts/record-demo.mjs --view desktop   # docs/demo/demo-desktop.mp4
```

| Файл | Кадр | Что внутри |
|---|---|---|
| `demo-mobile.mp4` | 780×1688 (390×844 @2x) | 28 сцен, ~2:10, подписи снизу над нижней навигацией |
| `demo-desktop.mp4` | 1440×900 | те же 28 сцен, подписи в правом нижнем углу |

Проход подробный: все экраны студента (главная, расписание день и неделя, успеваемость, вкладка долгов, зачётка, заявки, отклонённая заявка со справкой, пересдачи, подтверждение записи, уведомления, переписка, новая заявка, документы, профиль), деканата (сводка, очередь, карточка заявки, переписка, объявление, правка пары) и админки (пары, преподаватели, дисциплины, люди, семестры, модалка правки пары).

Каждый экран снимается в реальном браузере, длительность кадра фиксирована (4–5.5 с), подпись рисуется поверх страницы до снимка. Голоса нет — смысл несут экраны и подписи. Воспроизводится одной командой на свежем сиде, поэтому видео совпадает с демо.

Ниже — полный сценарий для версии с голосом, если понадобится.

| Время | Кадр | Что говорим |
|---|---|---|
| 0:00–0:15 | Страница входа | «Это концепт кабинета студента для конкурса, не официальный сервис. Четыре тестовых аккаунта: два студента, деканат и админ». |
| 0:15–0:40 | Вход первым студентом → главная | «Один экран отвечает на три вопроса: что сегодня, что изменилось, что с сессией. Светофор жёлтый: два долга, ближайший — 24 ноября». |
| 0:40–1:05 | Расписание, день и неделя | «Перенос виден как статус, а не как примечание: было 12:10, стало 14:00. Отмена — отдельным цветом и словом». |
| 1:05–1:30 | Успеваемость | «Светофор считают правила, не модель: статус и приоритет воспроизводимы. ИИ только переформулирует объяснение». |
| 1:30–1:50 | Заявки и карточка заявки | «Статус, срок в рабочих днях, причина отказа. История показывает, кто и когда менял статус». |
| 1:50–2:10 | Пересдачи | «Только незакрытые дисциплины: сданное пересдать нельзя. Перед записью — подтверждение с датой, аудиторией и числом мест». |
| 2:10–2:30 | Уведомления | «Объявления, переносы, статусы заявок и новые сообщения — всё в одном списке, с переходом в нужный раздел». |
| 2:30–2:55 | Новая заявка | «Справка за четыре шага: тип, назначение, формат, отправка. Срок — в рабочих днях, сразу видно дату». |
| 2:55–3:20 | Деканат: сводка и очередь | «Деканат видит очередь по сроку, а не по дате подачи. Меняет статус, причина отказа обязательна». |
| 3:20–3:40 | Деканат: переписка | «Ответ студенту уходит в его уведомления — ждать, пока он откроет раздел, не нужно». |
| 3:40–4:00 | Профиль | «Данные студента и границы доступа: чужую заявку по прямой ссылке не открыть». |
| 4:00–4:25 | Админка: пары и преподаватели | «Жюри правит базу без SSH и SQL: таблицы, поиск, создание и правка. Правка пары сразу видна студенту». |
| 4:25–4:50 | Телефон 360 px | «Тот же путь на телефоне: нижняя навигация, цели под палец, без горизонтальной прокрутки». |
| 4:50–5:00 | Проверка изоляции | «Второй студент не видит заявку первого: по прямой ссылке — «не найдено». Это проверяется скриптом, а не глазами». |

## Технические требования

- Разрешение: 1080×1920 (телефон) или 1280×720 (окно).
- Звук: микрофон, без музыки.
- Субтитры: не обязательны, но текст в кадре читается.
- Не показывать: `.env`, реальные почты, ключи, консоль с секретами.
- Хостинг видео: YouTube (unlisted), VK Видео, RuTube или Диск.

## Что подготовить до записи

1. `npm run seed` — свежие данные.
2. Заранее создать одну заявку первым студентом, чтобы было что показать в очереди.
3. Очистить уведомления нельзя намеренно: непрочитанные нужны для кадра.
4. Отключить уведомления ОС, чтобы не попадали в кадр.
