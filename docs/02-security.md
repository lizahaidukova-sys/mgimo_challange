# Безопасность и данные

## 1. Модель доступа

Правило одно: **основание доступа — сессия, а не идентификатор в запросе.**

| Ресурс | Студент | Сотрудник | Администратор |
|---|---|---|---|
| Профиль | только свой (`id` из сессии) | свой | свой |
| Расписание | своё (по группе из профиля) | редактирование | CRUD всех пар |
| Оценки | свои | просмотр по группе | через админку: дисциплины и люди |
| Заявки | свои, вложения только своих заявок | все, смена статуса, скачивание вложений | нет доступа к разделу |
| Переписка | своя, только с деканатом | все диалоги, ответ | нет доступа |
| Уведомления | свои | свои | свои |
| Админка `/api/admin/*` | 403 | 403 | полный CRUD шести сущностей |
| Аудит | нет | нет прямого доступа | записи о своих мутациях |

| Код ответа | Когда |
|---|---|
| 404 | ресурс не существует **или** принадлежит другому — специально неразличимо |
| 401 | нет сессии |
| 403 | сессия есть, но роли не хватает (staff-разделы, админка) |

403 используется только для ролей: он не раскрывает существование чужого ресурса. Вложение чужой заявки — 404, как и сама заявка.

Админка — отдельная роль, а не расширение staff: `requireAdmin` проверяет `role === 'admin'`. Сотрудник деканата получает 403 на `/api/admin/*`, это проверяется в `scripts/verify-idor.ts`. Себя администратор удалить не может, удаление сущности со связями блокируется отдельной проверкой.

## 2. Пароли

- Хранение: `scrypt` (N=16384, r=8, p=1, 64 байта), соль 16 байт на пользователя.
- Формат в БД: `scrypt$N$r$p$salt_b64$hash_b64`.
- Сравнение — `timingSafeEqual`.
- В открытом виде пароль существует только в памяти запроса.
- На экране входа — одинаковая ошибка для «нет пользователя» и «неверный пароль».
- Лимит попыток: 10 на e-mail за 10 минут, считается и для несуществующих адресов (в памяти процесса; для прототипа достаточно, ограничение зафиксировано).
- Проверено: 11-я попытка возвращает 429, успешный вход после этого работает.

Демо-пароли тестовых аккаунтов опубликованы намеренно — это требование конкурса, а не утечка. Пароли реальных людей не используются.

## 3. Сессии

| Свойство | Значение |
|---|---|
| Транспорт | `httpOnly`, `SameSite=Lax`, `Path=/`; `Secure` — когда `APP_ORIGIN` начинается с `https://`, иначе по http прототип не смог бы войти |
| Содержимое | случайный 32-байтный токен; в БД — только SHA-256 от него |
| Срок | 7 дней, продление при активности не более раза в сутки |
| Отзыв | `revoked_at` при выходе и смене пароля |
| CSRF | server actions + проверка `Origin` для небезопасных методов |

## 4. Секреты

| Где | Что |
|---|---|
| `.env` | `SESSION_SECRET`, `LLM_API_KEY`, путь к базе |
| `.env.example` | только имена и комментарии |
| `.gitignore` | `.env*`, `*.db`, `Исходные данные.md`, брифы |
| Клиент | ничего: переменных с префиксом `VITE_` в проекте нет |

Проверка перед отправкой:

```bash
rg -n "sk-|api[_-]?key|password\s*=" --glob '!node_modules' --glob '!.next'
rg -n "SESSION_SECRET|LLM_API_KEY" .next/static || echo "в клиенте ключей нет"
```

## 5. Валидация входа

- Все формы — zod-схемы, одинаковые на клиенте и сервере.
- Длины и перечисления ограничены; `payload_json` принимается только по белому списку полей шаблона.
- Вывод — React-экранирование, `dangerouslySetInnerHTML` не используется.
- Заголовки: `X-Content-Type-Options: nosniff`, `Referrer-Policy: strict-origin-when-cross-origin`, CSP без `unsafe-inline` для скриптов.

### 5a. Файлы заявок

| Риск | Что сделано |
|---|---|
| Подмена типа | белый список MIME: PDF, JPEG, PNG, WebP. Проверка на клиенте и на сервере; ZIP и исполняемые — 400 |
| Огромный файл | лимит 5 МБ на `express.raw`; пустое тело — 400 |
| Обход пути в имени | имя приходит от клиента и чистится: `path.basename`, вырезание `\u0000-\u001f<>:"/\\|?*`, обрезка до 120 символов |
| Файл на диске под чужим именем | хранится под `randomUUID()`, исходное имя только в базе |
| Выход за каталог при чтении | `path.resolve` + проверка префикса корня вложений |
| Подмена содержимого браузером | отдача с `Content-Type` из базы, `X-Content-Type-Options: nosniff`, `Content-Disposition: inline` с UTF-8 именем |
| Чужой файл по id | запрос джойнит `requests.user_id = сессия`; чужой и несуществующий — 404 |
| Скачивание из админки | отдельный staff-маршрут с `requireStaff`; студент получает 403 на staff-путь |
| Утечка в бэкап | каталог `data/attachments` в git не попадает, но входит в `attachments-*.tar.gz` рядом с базой |

## 6. Данные

- Все ФИО, группы, оценки, аудитории — вымышленные, из `db/seed.ts`.
- Нет телефонов, адресов, паспортов, номеров зачёток — только то, что нужно сценариям.
- Нет подключения к системам вуза, нет парсинга закрытых страниц.
- Нет аналитики с передачей персональных данных третьим лицам.
- База — файл вне git, создаётся сидом.
- Нативных зависимостей нет: поверхность атаки через скомпилированные модули отсутствует.

## 7. Аудит

`audit_log` пишет: вход (успех/провал), выход, создание заявки, смена статуса, публикация объявления, смена пары. В журнал не пишутся пароли, токены и полные payload'ы.

## 8. Проверки перед отправкой

| Проверка | Инструмент | Ожидание |
|---|---|---|
| Чужая заявка по прямому URL | `scripts/verify-idor.ts` | 404 у второго студента |
| Чужой профиль | тот же скрипт | редирект на свой профиль |
| Staff-раздел под студентом | скрипт | 403 |
| Секреты в репозитории | `rg` по шаблонам | 0 совпадений |
| Секреты в клиентском бандле | поиск по `.next/static` | 0 совпадений |
| Пароли в БД | `SELECT password_hash` | префикс `scrypt$`, не открытый текст |
| Куки | DevTools | `HttpOnly`, `SameSite=Lax` |

## 8a. Не выглядит официальным сервисом

- `robots.txt` закрывает индексацию целиком, в HTML — `<meta name="robots" content="noindex, nofollow">`.
- Дисклеймер в шапке и футере каждого экрана.
- Официальная символика вуза не используется, логотип собственный.
- Почему так: прототип не должен выдаваться за сервис МГИМО ни в поиске, ни в глазах студента, который случайно открыл ссылку.

## 9. Остаточные риски

| Риск | Почему принят | Что делать при развитии |
|---|---|---|
| Лимит попыток в памяти процесса | один инстанс, демо | вынести в БД/Redis |
| SQLite на одном узле | прототип, малая нагрузка | Postgres + пул соединений |
| Нет 2FA | не требуется конкурсом | добавить TOTP для сотрудников |
| LLM видит факты об учёбе | вымышленные данные; ключ серверный | анонимизация и согласие при реальных данных |
