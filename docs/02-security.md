# Безопасность и данные

## 1. Модель доступа

Правило одно: **основание доступа — сессия, а не идентификатор в запросе.**

| Ресурс | Студент | Сотрудник |
|---|---|---|
| Профиль | только свой (`id` из сессии) | список без контактов, только учебные данные |
| Расписание | своё (по группе из профиля) | редактирование |
| Оценки | свои | просмотр по группе |
| Заявки | свои | все, смена статуса |
| Уведомления | свои | публикация объявлений |
| Аудит | нет | чтение |

| Код ответа | Когда |
|---|---|
| 404 | ресурс не существует **или** принадлежит другому — специально неразличимо |
| 401 | нет сессии |
| 403 | сессия есть, роли не хватает (staff-разделы) |

403 используется только для ролей: он не раскрывает существование чужого ресурса.

## 2. Пароли

- Хранение: `scrypt` (N=16384, r=8, p=1, 64 байта), соль 16 байт на пользователя.
- Формат в БД: `scrypt$N$r$p$salt_b64$hash_b64`.
- Сравнение — `timingSafeEqual`.
- В открытом виде пароль существует только в памяти запроса.
- На экране входа — одинаковая ошибка для «нет пользователя» и «неверный пароль».
- Лимит попыток: 10 на e-mail за 10 минут (в памяти процесса; для прототипа достаточно, ограничение зафиксировано).

Демо-пароли тестовых аккаунтов опубликованы намеренно — это требование конкурса, а не утечка. Пароли реальных людей не используются.

## 3. Сессии

| Свойство | Значение |
|---|---|
| Транспорт | `httpOnly`, `SameSite=Lax`, `Secure` в production, `Path=/` |
| Содержимое | случайный 32-байтный токен; в БД — только SHA-256 от него |
| Срок | 7 дней, продление при активности не более раза в сутки |
| Отзыв | `revoked_at` при выходе и смене пароля |
| CSRF | server actions + проверка `Origin` для небезопасных методов |

## 4. Секреты

| Где | Что |
|---|---|
| `.env` | `SESSION_SECRET`, `LLM_API_KEY`, путь к базе |
| `.env.example` | только имена и комментарии |
| `.gitignore` | `.env*`, `*.db`, `Исходные данные.md`, брифы |
| Клиент | ничего: переменных `NEXT_PUBLIC_*` в проекте нет |

Проверка перед отправкой:

```bash
rg -n "sk-|api[_-]?key|password\s*=" --glob '!node_modules' --glob '!.next'
rg -n "SESSION_SECRET|LLM_API_KEY" .next/static || echo "в клиенте ключей нет"
```

## 5. Валидация входа

- Все формы — zod-схемы, одинаковые на клиенте и сервере.
- Длины и перечисления ограничены; `payload_json` принимается только по белому списку полей шаблона.
- Вывод — React-экранирование, `dangerouslySetInnerHTML` не используется.
- Заголовки: `X-Content-Type-Options: nosniff`, `Referrer-Policy: strict-origin-when-cross-origin`, CSP без `unsafe-inline` для скриптов.

## 6. Данные

- Все ФИО, группы, оценки, аудитории — вымышленные, из `db/seed.ts`.
- Нет телефонов, адресов, паспортов, номеров зачёток — только то, что нужно сценариям.
- Нет подключения к системам вуза, нет парсинга закрытых страниц.
- Нет аналитики с передачей персональных данных третьим лицам.
- База — файл вне git, создаётся сидом.

## 7. Аудит

`audit_log` пишет: вход (успех/провал), выход, создание заявки, смена статуса, публикация объявления, смена пары. В журнал не пишутся пароли, токены и полные payload'ы.

## 8. Проверки перед отправкой

| Проверка | Инструмент | Ожидание |
|---|---|---|
| Чужая заявка по прямому URL | `scripts/verify-idor.ts` | 404 у второго студента |
| Чужой профиль | тот же скрипт | редирект на свой профиль |
| Staff-раздел под студентом | скрипт | 403 |
| Секреты в репозитории | `rg` по шаблонам | 0 совпадений |
| Секреты в клиентском бандле | поиск по `.next/static` | 0 совпадений |
| Пароли в БД | `SELECT password_hash` | префикс `scrypt$`, не открытый текст |
| Куки | DevTools | `HttpOnly`, `SameSite=Lax` |

## 9. Остаточные риски

| Риск | Почему принят | Что делать при развитии |
|---|---|---|
| Лимит попыток в памяти процесса | один инстанс, демо | вынести в БД/Redis |
| SQLite на одном узле | прототип, малая нагрузка | Postgres + пул соединений |
| Нет 2FA | не требуется конкурсом | добавить TOTP для сотрудников |
| LLM видит факты об учёбе | вымышленные данные; ключ серверный | анонимизация и согласие при реальных данных |
