| Поле | Значение |

## 20.11.2026 — реализация

### И4. Стек: отказ от метафреймворка

| Поле | Значение |
|---|---|
| Задача | Выбрать клиент и сервер так, чтобы проверки доступа были явными |
| Промпт | стадия 4, `docs/05-promptbook.md` |
| Первый вариант | ассистент собрал каркас на Next.js: серверные компоненты и server actions |
| Проблема | путь запроса спрятан; для проверки «чужой id недоступен» пришлось бы читать фреймворк, а не свой код |
| Решение | React + Vite на клиенте, Express на сервере: каждый маршрут виден целиком |
| Итог | 39 проверок доступа читаются без фреймворка и воспроизводятся одной командой (на момент И14 их было 15) |

### И29. Админка: PATCH сбрасывал поля и падал на умолчаниях

| Поле | Значение |
|---|---|
| Задача | CRUD-панель для жюри: пары, преподаватели, аудитории, дисциплины, семестры, люди |

### И30. Админка: миграция роли и сессия после сброса демо

| Поле | Значение |
|---|---|
| Симптом 1 | вставка `role = 'admin'` в существующую базу падала на CHECK |
| Причина 1 | SQLite не меняет CHECK через `ALTER TABLE`; `CREATE TABLE IF NOT EXISTS` на готовой базе ничего не делает |
| Исправление 1 | пересоздание `users`: чтение `sqlite_master`, `PRAGMA foreign_keys=OFF`, копия строк, `DROP`, `RENAME`, затем `PRAGMA foreign_key_check` |
| Проверка 1 | на копии рабочей базы: 3 пользователя, 56 записей зачётки, 6 сессий, 9 уведомлений на месте; вставка admin проходит |
| Симптом 2 | после `reset-demo` панель выбрасывала на вход |
| Причина 2 | сид удаляет `sessions` и пересоздаёт пользователей с новыми id |

### И32. Запись на пересдачу срабатывала без подтверждения

|---|---|
| Отзыв | «При нажатии „Записаться“ разве не должно ничего вылазить? Кнопка нажимается, а когда и на какой день — непонятно» |

| Проверка | «Отмена» и Escape не меняют базу; запись после подтверждения появляется в списке и в блоке «Ближайшая запись»; на 360 px панель занимает всю ширину, прокрутки нет |

### И33. Студенту некуда приложить справку по требованию деканата

| Поле | Значение |
|---|---|
| Отзыв | «Деканат требует справку — студент её приложить не сможет» |
| Причина | у заявки был только текст: комментарий деканата видели, но загрузить файл было некуда |
| Решение | таблица `request_attachments` (метаданные) + файлы на диске в `data/attachments/<id заявки>/`; база не раздувается, бэкап базы не тянет мегабайты |
| Маршруты | `PUT /api/requests/:id/attachments` (сырые байты, без multipart), `GET /api/requests/:id/attachments/:aid` для автора, `GET /api/staff/requests/:id/attachments/:aid` для деканата |
| Защита | чужой id → 404, как и несуществующий; staff не грузит файлы за студента (403); к выполненной заявке — 400; только PDF/JPEG/PNG/WebP до 5 МБ; имя чистится от пути; файлы отдаются с `nosniff` |
| Дефект по ходу | имя файла на кириллице приходило кракозябрами: HTTP-заголовки не несут UTF-8. Клиент шлёт `encodeURIComponent`, сервер декодирует |
| Бэкап | `/usr/local/bin/dean-backup` теперь кладёт рядом архив `attachments-*.tar.gz`; попутно исправлен `pipefail`: `ls` по пустому шаблону валил юнит |
| Проверка | `npm run verify:idor` — восемь новых проверок: автор качает свой файл, другой студент 404, деканат 200, загрузка к чужой заявке 404, ZIP 400, staff 403 (на тот момент всего 35) |

### И34. Сообщения не попадали в уведомления

| Поле | Значение |
|---|---|
| Отзыв | «Если приходит сообщение студенту от деканата и наоборот — этого не видно» |
| Причина 1 | `sendMessage()` только вставлял строку в `messages`: раздел «Уведомления» про переписку не знал |
| Причина 2 | страница «Сообщения» обещала «ответ приходит сюда и в уведомления» — текст был, реализации не было |
| Причина 3 | колокольчик показывался только студенту: у деканата не было ни входа в уведомления, ни маршрута `/notifications` |
| Исправление 1 | `sendMessage()` создаёт уведомление `kind = 'message'`: студенту от деканата, всем `staff`/`admin` — от студента (с его ФИО в заголовке) |
| Исправление 2 | новый вид в `kindMeta` и ссылка на диалог: `/messages` для студента, `/staff/dialogs` для деканата |
| Исправление 3 | колокольчик у всех ролей, маршрут `/notifications` в ветке `role !== 'student'` |
| Исправление 4 | прочтение переписки гасит связанные уведомления: иначе бейдж горел после того, как студент всё прочитал. Открытие диалога деканатом гасит только уведомления этого студента |
| Проверка | `npm run verify:idor` — четыре новые: студент пишет → у деканата +1, `kind=message` в списке, деканат отвечает → у студента +1, открытая переписка гасит уведомление (итого 39) |
